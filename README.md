# 研究フワフワ大脱出 化学部テスト版

claude.ai のアカウントがなくても、スマホのブラウザで開ける版です。広場（ソーシャル機能）は外してあり、そのほかの機能（今日の一歩・研究タイマー・探究マップ・反応Lv・観測・図鑑）はすべて端末の中だけで動きます。サーバーに送られるデータはありません。効果音は初期設定で「なし」です（「マップ」画面の下で切り替えられます）。

## フォルダの中身

| ファイル | 役割 |
|---|---|
| index.html | アプリ本体 |
| manifest.webmanifest | 「ホーム画面に追加」したときの名前とアイコン |
| sw.js | 一度開けば、電波がなくても起動できるようにする仕組み |
| icon-192.png / icon-512.png | アイコン |
| apps-script/Code.gs | 結果を受け取るスプレッドシート用のコード（GitHubには上げなくてよい） |

アプリ本体の5つ（とREADME.md）は、GitHubの同じ場所に置いてください。

## 公開と結果の集め方（全体の流れ）

作業は3つのパートに分かれます。パソコンで行うのがおすすめです。所要時間は合わせて30〜40分ほどです。

- パートA：GitHub Pages でアプリを公開する（部員に渡すURLができる）
- パートB：Google スプレッドシートに受け取り口を作る（結果が届く場所ができる）
- パートC：アプリに受け取り口のURLを書き込む（「担当者に送る」ボタンが使えるようになる）

パートBとCをしなくても、アプリは使えます。その場合、結果は部員にコピーして送ってもらう形になります。

## パートA：GitHub Pages でアプリを公開する

### A-1 zip を展開する
1. chem-test.zip をパソコンに保存し、右クリック →「すべて展開」（Mac はダブルクリック）。
2. 中に index.html、manifest.webmanifest、sw.js、icon-192.png、icon-512.png、README.md と、apps-script フォルダがあることを確かめます。

### A-2 GitHub のアカウントを作る
1. https://github.com を開き、「Sign up」を押します。
2. メールアドレス、パスワード、ユーザー名を入れます。ユーザー名は公開URLに入るので、本名を避けた短い英数字がおすすめです（例：fuwafuwa-lab）。
3. 届いたメールの確認コードを入力すれば完了です。

### A-3 リポジトリ（ファイルの置き場所）を作る
1. ログイン後、右上の「＋」→「New repository」を押します。
2. 「Repository name」に kenkyu-fuwafuwa と入れます（英小文字とハイフンがおすすめ。これもURLに入ります）。
3. 公開範囲は「Public」を選びます。無料のアカウントで GitHub Pages を使うには Public が必要です。中身はアプリのファイルだけで、部員の記録は入りません。
4. 「Add a README file」などのチェックは付けずに、「Create repository」を押します。

### A-4 ファイルをアップロードする
1. 作ったリポジトリの画面に出る「uploading an existing file」というリンクを押します（見つからないときは「Add file」→「Upload files」）。
2. 展開したフォルダの中から、index.html、manifest.webmanifest、sw.js、icon-192.png、icon-512.png、README.md の6つを選んで、まとめて画面にドラッグします。
   - **フォルダごとではなく、ファイルを直接**ドラッグしてください。フォルダごと入れると、公開URLを開いたときに「404」になります。
   - apps-script フォルダはアップロードしなくてかまいません（パートBで使います）。
3. 画面下の「Commit changes」を押します。

### A-5 公開の設定をする
1. リポジトリ上部の「Settings」を押します。
2. 左のメニューの「Pages」を押します。
3. 「Build and deployment」の「Source」が「Deploy from a branch」になっていることを確かめます。
4. 「Branch」を「main」、その右を「/ (root)」にして「Save」を押します。
5. 1〜3分待ってから画面を再読み込みすると、上に「Your site is live at …」と表示されます。そのURLが部員に渡すリンクです。
   - 形は https://（ユーザー名）.github.io/kenkyu-fuwafuwa/ です。
   - なかなか出ないときは、リポジトリ上部の「Actions」で公開作業の進み具合が見られます。緑のチェックが付けば完了です。

### A-6 開けるか確かめる
1. そのURLをパソコンとスマホで開き、アプリが表示されるか確かめます。
2. 「404」と出たら、A-4 でファイルがフォルダの中に入っていないかを確認してください。

## パートB：Google スプレッドシートに受け取り口を作る

### B-1 スプレッドシートを作る
1. Google ドライブを開き、「新規」→「Google スプレッドシート」を選びます。
2. 名前を「フワフワ テスト結果」などに変えます。

### B-2 受け取り用のコードを貼る
1. スプレッドシートのメニューで「拡張機能」→「Apps Script」を押します。新しいタブが開きます。
2. 最初から入っている数行のコードを全部消します。
3. apps-script フォルダの Code.gs をメモ帳などで開き、中身を全部コピーして貼り付けます。
4. 上のほうにある「const TOKEN = 'ここを合言葉に変える';」の、'' の中を好きな合言葉に変えます（例：'fuwa-2026-chem'）。半角英数字がおすすめです。
5. 保存ボタン（フロッピーの絵）を押します。

### B-3 ウェブアプリとして公開する
1. 右上の「デプロイ」→「新しいデプロイ」を押します。
2. 「種類の選択」の歯車マークから「ウェブアプリ」を選びます。
3. 次のように設定します。
   - 説明：何でもかまいません（例：テスト結果の受け取り）
   - 次のユーザーとして実行：「自分」
   - アクセスできるユーザー：「全員」（部員はGoogleにログインしていなくても送れるようにするため）
4. 「デプロイ」を押すと、アクセスの承認を求められます。「アクセスを承認」→ 自分のアカウントを選びます。
5. 「このアプリは Google で確認されていません」と出たら、「詳細」→「（プロジェクト名）（安全ではないページ）に移動」→「許可」と進みます。自分で作ったコードなので問題ありません。
6. 最後に表示される「ウェブアプリ」の URL（https://script.google.com/macros/s/…/exec）をコピーしておきます。
7. 確認として、そのURLをブラウザで開いてみてください。「受け取り口は動いています」と出れば成功です。

## パートC：アプリに受け取り口を書き込む

1. GitHub のリポジトリで index.html を開き、右上の鉛筆マーク（Edit this file）を押します。
2. キーボードの Ctrl＋F（Mac は ⌘＋F）で「RESULT_ENDPOINT」を探します。次の2行があります。
   - const RESULT_ENDPOINT='';
   - const RESULT_TOKEN='';
3. 次のように '' の中に書き込みます。記号の ' は消さないでください。
   - const RESULT_ENDPOINT='（B-3 でコピーしたURL）';
   - const RESULT_TOKEN='（B-2 で決めた合言葉）';
4. 右上の「Commit changes…」→ もう一度「Commit changes」を押します。
5. 1〜3分待ってから、公開URLをスマホで開き、「マップ」→「テスト結果を送る」→「担当者に送る」を押します。スプレッドシートに「results」というシートができ、1行増えていれば完成です。

### 部員に配ったあとでアプリを書き換えたとき
sw.js も鉛筆マークで開き、1行目近くの「kfw-chemtest-v1」を「kfw-chemtest-v2」のように数字を1つ増やしてから Commit してください。これをしないと、部員のスマホに古い版が残ることがあります。部員の記録は消えません。

### Code.gs を書き換えたとき
Apps Script の「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン」を「新バージョン」にして「デプロイ」を押します。URLは変わらないので、アプリの書き換えはいりません。

### 安全のために
- 受け取り口のURLと合言葉は、アプリの中に書かれているので、詳しい人なら見ることができます。届くのは参加コードと回数だけなので大きな問題はありませんが、テストが終わったら「デプロイを管理」からこのデプロイを「アーカイブ」して受け取りを止めてください。
- 同じ参加コードから何度も届いた場合は、いちばん新しい行（receivedAt が最も遅いもの）を使ってください。

## 配る前に自分で確認すること

- キャラクターが研究ノートの落書き風に表示され、線が少しふるえているか。ホームでタップすると跳ねるか。
- 初回設定のあと「はじめての観測をする」で、1回観測できるか。
- 今日の一歩が問いに関するもの（マップの「課題の設定」の「『なぜ』を調べられる形に直そう」など）のとき、「問いの型」が表示され、押すと興味のある分野の例が出るか。
- 「マップ」の上にある「問いのくらべっこ」で3問答えられるか。
- 今日の一歩が論文に関するもの（マップの「課題の設定」など）のとき、J-STAGEなどのボタンでサイトが開き、アプリ側で研究タイマーが始まるか。
- 「ホーム画面に追加」したアイコンから起動できるか。
- 一度開いたあと機内モードにしても、起動して「研究を始める」が押せるか。
- 3分以上研究して終えると、エネルギーが増えてゲージが動くか。

## 下書きメモについて（部員と顧問の先生に伝えてください）

研究中の画面にある「メモ・写真」から、気づいたことや写真を残せます。作成した時刻は自動で記録され、あとから変えられません。書き直すと元の文は取り消し線で残ります。研究を終えるとその回のメモが時刻順に並ぶので、それを見ながら紙の研究ノートに写します。

- これは紙のノートに写すための下書きです。正式な記録は必ず紙の研究ノートに残してください。
- 「紙に写した」メモは7日後に自動で消えます。まだ写していないメモは消えませんが、端末の保存データなので、機種変更やブラウザのデータ削除で失われることがあります。
- メモと写真は端末の中だけに保存され、テスト結果には件数だけが含まれます（内容や写真は送られません）。
- 実験中は、手袋を外すなど安全を確かめてからスマホを触るよう、部のルールを決めておいてください。
- 人の顔や、外に出してはいけない資料が写った写真は「写真を消す」で消せます。消したことは時刻とともに記録されます。

## パソコンで使う

同じURLをパソコンのブラウザで開くと、横長の画面に合わせた配置（左にメニュー、ホームは2列）になります。研究中はブラウザのタブに経過時間が表示されるので、論文を読みながら別のタブで作業していても時間が分かります。ChromeやEdgeでは、アドレスバーの「インストール」ボタンからアプリとして入れることもできます。

記録は端末ごとに保存されるため、スマホとパソコンの記録は別々になります（テスト版には同期機能がありません）。テスト中は、どちらか一方の端末で使ってもらうよう伝えてください。

## 部員への配り方

URL を QR コードにして配るのがいちばん簡単です。最初の1回だけは通信できる状態で開いてもらってください。

**iPhone の部員には必ず「ホーム画面に追加」をしてもらってください。** Safari は、7日間開かなかったサイトの保存データを消すことがあります。ホーム画面に追加したアプリはこの対象外になるので、テスト中に記録が消えるのを防げます。Android の Chrome では、メニューの「ホーム画面に追加」または「アプリをインストール」を使います。

1台の端末をほかの人と共有すると記録が混ざります。共有する場合は、次の人に渡す前に「マップ」画面の一番下にある「データを消去」を使ってください。

## テストの流れ（例：2週間）

1. 使う前のアンケートに答えてもらう。初回設定のあとに表示される「テスト参加コード」（例：KF-7Q3M）も書いてもらう。
2. 2週間、ふだんの部活の研究の中で自由に使ってもらう。使い方の指示はしない。
3. 期間の最後に「マップ」→「テスト結果を送る」→「担当者に送る」を押してもらう（パートB・Cをしていない場合は「コピーする」や「共有する」で送ってもらう）。途中で何度送ってもかまいません。
4. 使ったあとのアンケートと、短いインタビューを行う。

参加コードを使えば、アンケートと結果を名前なしで結びつけられます。

## 送られてくる結果

上半分は人が読むための要約で、`---` の下の1行は集計用の JSON です。JSON の行だけを集めれば、スプレッドシートで一覧にできます。

含まれるもの：参加コード、論文検索ボタン（J-STAGE・CiNii・Google Scholar）を押した回数、下書きメモ・写真の件数（内容は含まない）、問いのくらべっこの回数と正解数、問いの型を見た回数、使った日数、研究に戻った回数、研究した日数、3日以上空いてからの再開回数、研究時間の合計と中央値、紙ノート「書いた／あとで書く」の回数、反応Lv、観測回数、発見数、探究マップの足あと、「ほかの一歩にする」やキャラクターをタップした回数、研究ごとの日付・分数・探究の段階。
